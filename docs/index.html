1. Entendiendo la Autenticación: ¿Por qué JWT?

Cuando un usuario inicia sesión, el servidor debe recordar su identidad en las siguientes peticiones HTTP. Hay dos patrones principales para lograr esto:

💡 Concepto Clave: Las HTTP son peticiones stateless (sin memoria). Los tokens JWT le dan al cliente un pasaporte firmado digitalmente para identificarse en cada llamada sin guardar datos en el servidor.
Criterio Sesiones en Servidor (Cookies / Memory) JWT Bearer Token (Nuestro Enfoque)
Persistencia Guarda sesiones en memoria RAM o Base de Datos. Stateless: La firma matemática valida los datos.
Escalabilidad Requiere sincronizar bases de datos entre servidores. Alta: Cualquier servidor valida el token con la clave secreta.
Desacoplamiento Dificulta llamadas de frontend React en dominios o puertos distintos. Universal: Se envía en el header Authorization: Bearer <token>.

2. Arquitectura de Control de Acceso Backend (RBAC)

Para proteger rutas sensibles, el backend encadena dos middlewares en Express:

Paso 1: Verificación de Firma (verifyToken)

Comprueba que el token sea auténtico y extrae el userId y userRole del payload.

export const verifyToken = (req: AuthRequest, res: Response, next: NextFunction) => {
  const authHeader = req.headers.authorization;
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    return res.status(401).json({ message: 'No token provided' });
  }

  const token = authHeader.split(' ')[1];
  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET as string) as TokenPayload;
    req.userId = decoded.usuario_id ?? decoded.id;
    req.userRole = decoded.rol_id ?? 1;
    next();
  } catch (error) {
    return res.status(401).json({ message: 'Invalid token' });
  }
};

Paso 2: Autorización por Rol (requireRole)

Revisa si el rol extraído tiene permiso para acceder a la ruta requerida.

export const requireRole = (requiredRole: number) => {
  return (req: AuthRequest, res: Response, next: NextFunction) => {
    if (Number(req.userRole) !== requiredRole) {
      return res.status(403).json({ error: 'Acceso denegado. Permisos insuficientes.' });
    }
    next();
  };
};

3. Protección de Vistas en el Frontend (React Router)

En React se utiliza el componente ProtectedRoute para envolver las vistas privadas e impedir que usuarios sin sesión accedan desde la URL.

export const ProtectedRoute = ({ children }: { children: ReactNode }) => {
  const { isAuthenticated, loading } = useAuth();

  if (loading) return <div>Cargando...</div>;
  if (!isAuthenticated) return <Navigate to="/login" replace />;

  return <>{children}</>;
};
