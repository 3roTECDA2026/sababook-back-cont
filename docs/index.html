📘 Manual de Aprendizaje: Arquitectura & Seguridad Web

Guía didáctica sobre conceptos de autenticación, autorización por ruteo y buenas prácticas

1. Conceptos Fundamentales: Autenticación vs Autorización

En el desarrollo web es clave diferenciar ambos términos:

  • Autenticación (¿Quién sos?): Proceso para validar la identidad del usuario (ej. verificando credenciales).
  • Autorización (¿A qué tenés acceso?): Control de acceso para determinar si un usuario autenticado puede ejecutar una ruta o acción.

2. Autorización por Ruteo (Routing-Based Authorization)

💡 ¿Por qué Autorización por Ruteo? En lugar de dispersar condicionales dentro de cada controlador o vista, la autorización por ruteo declara los permisos directamente en la capa de transporte (rutas/endpoints). Esto garantiza que ninguna petición acceda a la lógica interna sin haber superado los filtros de acceso.

A. Backend: Interceptores de Ruta (Middlewares en Express)

Las rutas definen explícitamente su nivel de protección antes de llamar al controlador:

// Definición declarativa en la capa de ruteo (router)
import { Router } from 'express';
import { verifyToken, requireRole } from '@/middleware/auth.middleware';
import moderationController from '@/controllers/moderation.controller';

const router = Router();

// Ruta pública
router.get('/public-info', publicController.getInfo);

// Autorización por ruteo: requiere autenticación Y rol de Administrador (ID 1)
router.post('/moderacion/config', verifyToken, requireRole(1), moderationController.saveConfig);

B. Frontend: Protección de Rutas (React Router)

En el cliente, las vistas se agrupan en el enrutador aplicando protección previa antes de renderizar la página:

// AppRouter.tsx
import { Routes, Route } from 'react-router-dom';
import { ProtectedRoute } from '@/components/ProtectedRoute';

export const AppRouter = () => (
  <Routes>
    <Route path="/login" element={<LoginPage />} />

    {/* Autorización por Ruteo en Frontend */}
    <Route path="/admin" element={
      <ProtectedRoute requiredRole={1}>
        <AdminDashboardPage />
      </ProtectedRoute>
    } />
  </Routes>
);

3. Modelos de Autenticación: Sesiones vs JWT

Aspecto Sesiones en Servidor (Stateful) JWT Bearer Token (Stateless)
Almacenamiento El servidor guarda una tabla de sesiones activas. El servidor valida la firma matemática del token.
Escalabilidad Requiere bases de datos compartidas (Redis) entre servidores. Cualquier nodo del backend valida el token con la clave secreta.
