⚡ Guía: Alternativas de Frameworks y Patrones

Comparativa de Middlewares en Express vs Hooks en Fastify vs Guards en NestJS

1. Alternativas de Backend en Node.js

Aunque Express es el estándar más difundido, existen alternativas modernas de arquitectura:

  • Fastify: Basado en esquema JSON y arquitectura de Hooks (onRequest, preHandler) para máximo rendimiento.
  • NestJS: Basado en TypeScript con arquitectura orientada a objetos (Decoradores, Guards, Interceptors).

2. Alternativa en Fastify: `onRequest` Hook

📦 Importaciones requeridas:
import Fastify from 'fastify';

En Fastify, los middlewares se reemplazan por Hooks de ciclo de vida:

// server.ts (Fastify)
const fastify = Fastify();

fastify.addHook('onRequest', async (request, reply) => {
  const token = request.headers.authorization?.split(' ')[1];
  if (!token) {
    reply.code(401).send({ error: 'No autorizado en Fastify' });
  }
});

3. Alternativa en NestJS: `AuthGuard`

📦 Importaciones requeridas:
import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';
import { Observable } from 'rxjs';

En NestJS, la autorización se maneja mediante Guards (Guardias) declarativos:

@Injectable()
export class RolesGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest();
    return request.user?.rol_id === 1; // Retorna true para permitir o false para 403 Forbidden
  }
}

4. Casos de Éxito vs Falla en Alternativas

✅ Caso de Éxito: NestJS RolesGuard

El decorador @UseGuards(RolesGuard) ejecuta la función canActivate() retornando true.

➜ NestJS permite el ingreso al método del controlador de la ruta.

❌ Caso de Falla: Fastify Hook Reject

El Hook onRequest ejecuta reply.code(401).send(...) sin invocar el handler final.

➜ La conexión HTTP se cierra inmediatamente enviando respuesta JSON de error.
