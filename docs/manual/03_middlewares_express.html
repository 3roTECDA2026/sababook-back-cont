⚙️ Guía: Arquitectura de Middlewares en Express

Patrón Chain of Responsibility e Interceptores de Pipeline

1. ¿Qué es un Middleware en Express?

Un middleware es una función con acceso a los objetos de solicitud (req), respuesta (res) y a la siguiente función middleware (next) en el ciclo de solicitud-respuesta.

  • Ejecuta cualquier código.
  • Realiza cambios en la solicitud o en el objeto de respuesta.
  • Finaliza el ciclo de solicitud o invoca next().

2. Middleware de Auditoría y Logging (`requestLogger`)

📦 Importaciones requeridas:
import { Request, Response, NextFunction } from 'express';

Registra el método HTTP, la URL y el tiempo de respuesta de cada petición:

export const requestLogger = (req: Request, res: Response, next: NextFunction) => {
  const start = Date.now();
  res.on('finish', () => {
    const duration = Date.now() - start;
    console.log(`[${req.method}] ${req.originalUrl} - ${res.statusCode} (${duration}ms)`);
  });
  next();
};

3. Middleware Centralizado de Errores (`errorHandler`)

📦 Importaciones requeridas:
import { Request, Response, NextFunction } from 'express';

Captura excepciones lanzadas en cualquier controlador evitando la caída del servidor:

export const errorHandler = (err: any, req: Request, res: Response, next: NextFunction) => {
  const status = err.status || 500;
  console.error(`❌ Error [${status}]: ${err.message}`);
  res.status(status).json({
    error: true,
    message: err.message || 'Error interno del servidor'
  });
};

4. Casos de Éxito vs Falla en Pipeline de Middlewares

✅ Caso de Éxito: Ejecución Continuada

Cada middleware llama exitosamente a next() (Logger ➜ Auth ➜ Controller ➜ Response).

➜ La petición completa su ciclo con estado HTTP 200 OK.

❌ Caso de Falla: Excepción Capturada por Middleware de Errores

Ocurre una falla inesperada en la base de datos dentro del controlador y se invoca next(error).

➜ Express se saltea los middlewares restantes y salta directo al errorHandler de 4 parámetros retornando 500 Internal Server Error.
