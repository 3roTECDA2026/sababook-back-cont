⚙️ Guía: Fundamentos Básicos de Express y Middlewares

Explicación detallada de `req`, `res`, `next()`, asignación de datos y manejo de errores

1. Objetos Fundamentales: `req`, `res` y `next`

Toda función de middleware en Express recibe obligatoriamente tres argumentos:

ParámetroTipoPropósito y Función
req (Request) Object Representa la solicitud HTTP entrante (headers, body, query params, IP). Permite adosar variables personalizadas (ej: req.userRole).
res (Response) Object Representa la respuesta HTTP. Contiene métodos para responder al cliente (res.json(), res.status(), res.send()).
next Function Función callback que le indica a Express: "Terminé mi tarea en este middleware, pasale el control al siguiente middleware en la cadena".

2. ¿Cómo funciona `next()`? Sus 3 variaciones

La función next altera drásticamente el flujo de la aplicación según cómo se llame:

1. `next()` (Sin argumentos)

Pasa el control de forma limpia al siguiente middleware o controlador registrado en la ruta.

2. `next(err)` (Con un objeto de error o mensaje)

Le indica a Express que ocurrió un fallo. Express se salta inmediatamente TODOS los middlewares normales restantes y busca el manejador global de errores.

3. `next('route')` (Salto de ruta)

Comportamiento especial: se salta el resto de middlewares de la pila actual y pasa a la siguiente ruta configurada.

3. Asignar datos a `req` entre Middlewares

📦 Importaciones requeridas:
import { Request, Response, NextFunction } from 'express';

Dado que req es el mismo objeto JavaScript compartido durante toda la vida de la petición HTTP, un middleware puede enriquecerlo con datos para que el controlador final los consuma:

// Middleware 1: Adjunta usuario a req
export const setContext = (req: Request, res: Response, next: NextFunction) => {
  (req as any).userData = { id: 99, email: 'admin@sababook.com' };
  next(); // Continuar al controlador
};

// Controlador Final: Lee userData cargado por el middleware
export const getProfile = (req: Request, res: Response) => {
  const user = (req as any).userData;
  res.json({ message: `Perfil de ${user.email}` });
};

4. Manejador Global de Errores (4 Parámetros)

📦 Importaciones requeridas:
import { Request, Response, NextFunction } from 'express';

A diferencia de los middlewares estándar de 3 parámetros, el middleware de captura de errores de Express se reconoce ÚNICAMENTE por tener 4 parámetros (err, req, res, next):

// error.middleware.ts
export const globalErrorHandler = (err: any, req: Request, res: Response, next: NextFunction) => {
  console.error('🔥 Error no capturado:', err);
  res.status(err.status || 500).json({
    ok: false,
    error: err.message || 'Error interno del servidor'
  });
};

Cualquier middleware que llame a next(new Error("Algo falló")) o lance una excepción terminará aquí.
