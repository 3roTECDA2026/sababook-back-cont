3. Verificación de JWT (`verifyToken`)

📦 Importaciones requeridas:
import { Request, Response, NextFunction } from 'express';
import jwt from 'jsonwebtoken';

Middleware backend dedicado exclusivamente a validar el token de entrada:

// auth.middleware.ts
export const verifyToken = (req: Request, res: Response, next: NextFunction) => {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ message: 'No token' });
  req.userRole = (jwt.verify(token, process.env.JWT_SECRET!) as any).rol_id;
  next();
};

3B. `verifyToken` — Casos de Éxito vs Falla

✅ Caso de Éxito: Token Válido

Se envía el encabezado Authorization: Bearer eyJhbGci.... El token es legítimo y contiene { user_id: 42, rol_id: 1 }.

➜ req.userRole toma el valor 1 y se ejecuta next() pasando el control al siguiente middleware.

❌ Caso de Falla 1: Token Ausente

No se incluye el encabezado Authorization.

➜ Retorna de inmediato HTTP 401 Unauthorized con { message: "No token" }.

❌ Caso de Falla 2: Token Inválido o Expirado

El token está alterado o venció su tiempo de expiración.

➜ jwt.verify() lanza una excepción y la petición se detiene.

4. Control de Roles (`requireRole`)

📦 Importaciones requeridas:
import { Request, Response, NextFunction } from 'express';

Middleware backend encargado únicamente de autorizar según el rol:

// auth.middleware.ts
export const requireRole = (roleId: number) => (req: Request, res: Response, next: NextFunction) => {
  if (req.userRole !== roleId) return res.status(403).json({ error: 'Acceso denegado' });
  next();
};

4B. `requireRole` — Casos de Éxito vs Falla (Ejemplo de Rol)

✅ Caso de Éxito: Rol Coincidente (Admin = 1)

El parámetro requerido es requireRole(1) y el usuario tiene req.userRole === 1 (Admin).

➜ La condición se cumple y se ejecuta next() para continuar al controlador.

❌ Caso de Falla: Rol Insuficiente (Alumno = 2)

La ruta requiere requireRole(1) pero el usuario tiene req.userRole === 2 (Alumno).

➜ Retorna HTTP 403 Forbidden con { error: "Acceso denegado" } impidiendo la acción.

5. Declaración en Express Router

📦 Importaciones requeridas:
import { Router } from 'express';
import { verifyToken, requireRole } from '@/middleware/auth.middleware';
import moderationController from '@/controllers/moderation.controller';

Composición declarativa de middlewares en la definición del endpoint:

// routes.ts
const router = Router();
router.post('/admin/config', verifyToken, requireRole(1), moderationController.saveConfig);

6. Frontend Router Protegido

📦 Importaciones requeridas:
import React from 'react';
import { Navigate } from 'react-router-dom';
import { useAuth } from '@/context/AuthContext';

Componente envoltorio ProtectedRoute para React Router:

// ProtectedRoute.tsx
export const ProtectedRoute = ({ children, requiredRole }) => {
  const { isAuthenticated, user, loading } = useAuth();
  if (loading) return <div>Cargando...</div>;
  if (!isAuthenticated) return <Navigate to="/login" replace />;
  if (requiredRole && user?.rol !== requiredRole) return <Navigate to="/unauthorized" replace />;
  return <>{children}</>;
};

6B. `ProtectedRoute` — Casos de Éxito vs Falla en React

✅ Caso de Éxito: Usuario Autenticado con Rol Correcto

isAuthenticated === true y user.rol === 1.

➜ Renderiza directamente el componente hijo <AdminPage />.

❌ Caso de Falla 1: Usuario No Autenticado (Sin Sesión)

isAuthenticated === false.

➜ Redirige automáticamente al login: <Navigate to="/login" replace />.

❌ Caso de Falla 2: Rol Insuficiente

user.rol === 2 (Alumno) e intenta acceder a ruta con requiredRole={1}.

➜ Redirige a vista no autorizada: <Navigate to="/unauthorized" replace />.
