📘 Guía: Autenticación y Autorización JWT

Presentación interactiva por secciones (Single Responsibility Principle)

1. Autenticación vs Autorización

Diferencias fundamentales entre verificación de identidad y control de acceso:

CriterioAutenticaciónAutorización
Pregunta clave¿Quién sos?¿Qué podés hacer?
MomentoAl iniciar sesión.En cada petición protegida.
Error HTTP401 Unauthorized403 Forbidden

2. Sesiones (Stateful) vs JWT (Stateless)

Comparativa de arquitectura para la gestión de estado de usuario:

CriterioSesiones (Stateful)JWT (Stateless)
ServidorGuarda ID de sesión en RAM / DB.Sin estado en servidor.
MecanismoCookie enviada automáticamente.Encabezado Authorization: Bearer.
EscalabilidadRequiere sincronizar sesiones.Alta (firma criptográfica).

3. Verificación de JWT (`verifyToken`)

Middleware backend dedicado exclusivamente a validar el token de entrada:

// auth.middleware.ts
export const verifyToken = (req, res, next) => {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ message: 'No token' });
  req.userRole = jwt.verify(token, process.env.JWT_SECRET).rol_id;
  next();
};
💡 Responsabilidad Única: Solo verifica la validez del JWT y extrae los datos del payload. No verifica permisos específicos.

4. Control de Roles (`requireRole`)

Middleware backend encargado únicamente de autorizar según el rol:

// auth.middleware.ts
export const requireRole = (roleId) => (req, res, next) => {
  if (req.userRole !== roleId) return res.status(403).json({ error: 'Acceso denegado' });
  next();
};
💡 Responsabilidad Única: Asume que la identidad ya fue verificada previamente por verifyToken y compara únicamente el nivel de acceso.

5. Declaración en Express Router

Composición declarativa de middlewares en la definición del endpoint:

// routes.ts
router.post('/admin/config', verifyToken, requireRole(1), adminController.save);
💡 Responsabilidad Única: El Router se limita a definir el pipeline: 1° verifyToken, 2° requireRole(1) y 3° adminController.save.

6. Frontend Router Protegido

Componente envoltorio ProtectedRoute para React Router:

// ProtectedRoute.tsx
export const ProtectedRoute = ({ children, requiredRole }) => {
  const { isAuthenticated, user, loading } = useAuth();
  if (loading) return <div>Cargando...</div>;
  if (!isAuthenticated) return <Navigate to="/login" replace />;
  if (requiredRole && user?.rol !== requiredRole) return <Navigate to="/unauthorized" replace />;
  return <>{children}</>;
};
