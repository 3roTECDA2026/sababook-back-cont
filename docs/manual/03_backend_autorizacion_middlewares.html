Capítulo 3: Autorización Backend con Middlewares

Manual de Aprendizaje — Instituto 166

🛡️ Paso 1: Verificación de Firma JWT (`verifyToken`)

El primer interceptor comprueba que la petición incluya un token auténtico y que no haya sido alterado:

// Interceptor 1: Verificar firma JWT (verifyToken)
export const verifyToken = (req, res, next) => {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ message: 'No token' });
  
  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.userRole = decoded.rol_id;
    next(); // La firma es válida: avanza al siguiente paso
  } catch {
    return res.status(401).json({ message: 'Invalid token' });
  }
};
Explicación: Extrae el encabezado Authorization: Bearer <token>. Si el token no existe o la clave JWT_SECRET no coincide con la firma, detiene la ejecución inmediatamente respondiendo 401 Unauthorized. Si es válido, inyecta el rol_id dentro del objeto req.

🔒 Paso 2: Control de Acceso por Rol (`requireRole`)

El segundo interceptor evalúa si el usuario autenticado tiene el nivel de privilegio requerido:

// Interceptor 2: Verificar Rol (requireRole)
export const requireRole = (roleId) => (req, res, next) => {
  if (req.userRole !== roleId) {
    return res.status(403).json({ error: 'Acceso denegado' });
  }
  next(); // El rol coincide: avanza al controlador
};
Explicación: Es una función de orden superior que recibe el ID del rol necesario. Compara `req.userRole` (inyectado previamente por `verifyToken`). Si el usuario no posee ese rol, responde `403 Forbidden` deteniendo la petición antes de llegar al controlador.

🚦 Paso 3: Encadenamiento en la Capa de Ruteo (Router)

Finalmente, unimos los interceptores en la definición de la ruta:

// Declaración en Router
router.post('/admin/config', verifyToken, requireRole(1), adminController.save);
Explicación: Declaramos las reglas de acceso directamente en el router. Express ejecuta la cadena de izquierda a derecha: primero valida la identidad (`verifyToken`), luego valida el rol (`requireRole(1)`), y solo si ambos aprueban, ejecuta la lógica del controlador (`adminController.save`).
